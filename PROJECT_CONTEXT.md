## 1. Что это и где работает

**SUNOBOOM** — русскоязычная музыкальная мастерская для работы с жанрами, идеями песен, текстами, промптами Suno, аранжировками, артистами и собственными треками. Продукт задуман для **закрытого круга по приглашению**, а не как публичная соцсеть.

- **Единственный основной репозиторий:** https://github.com/nick-osinskiy/SUNOBOOM
- **Ветка:** `main`; продолжать существующую реализацию, не создавать новый сайт или отдельный HTML-прототип.
- **Опубликованный сайт:** https://nick-osinskiy.github.io/SUNOBOOM/
- **Хостинг:** GitHub Pages, главная страница `index.html`.
- **Важно о приватности:** репозиторий и Pages на момент проверки публичны. Сама идея доступа «по приглашениям» **не означает реализованную авторизацию**: серверного ограничения доступа пока не подтверждено.

## 3. Реальная архитектура на v0.110

Это **гибридный сайт**, а не полностью перенесённое Vue SPA.

- **Legacy shell:** большой `index.html` и корневые `*.js`/`*.css`; собственные `go()`, `view.nav`, `render()`, делегированные `data-action`. Старые функции продолжают управлять навигацией, бизнес-логикой и хранением данных.
- **Новый UI:** Vue 3 (`src/vue/`) подключается *поэтапно* только к выделенным контейнерам через `src/vue/entry.js`, `VueFeatureHost.vue` и `legacy*Bridge.js`. Не монтировать Vue поверх всего `#app` и не допускать конкуренции Vue и legacy-рендера за один DOM-узел.
- **Bootstrap:** `src/vue/bootstrap.js`; production-включение через метатег `sunoboom-vue-nav=enabled`, присутствующий в `index.html` на v0.109. При сбое Vue должен остаться доступен legacy fallback.
- **Сборка:** Vite 8, Vue 3.5, Pinia 3, установлен Vue Router 4. Vue Router **не является источником текущей маршрутизации**; Pinia не должна создавать вторую копию пользовательских данных. Node.js `>=22.12.0`.
- **Production bundle:** `dist/vue/sunoboom-vue.js` и `dist/vue/sunoboom-vue.css` публикуются вместе со старым сайтом. `.github/workflows/vue-navigation.yml` запускает сборку, проверки и при необходимости коммит проверенных assets.
- **Нет подтверждённого рабочего серверного API, защищённых учётных записей или облачной синхронизации.** Не предполагать их наличия.

## 5. Пользовательские данные — не потерять

Основное хранение **локальное, в браузере**, без синхронизации между устройствами:
- `localStorage['sunoboom-v1']` — общие проекты, идеи, избранное, промпты и другие записи.
- `localStorage['sunoboom-arrangement-v066']` — черновик аранжировщика.
- `localStorage['sunoboom-my-songs-v1']` — карточки песен и версии.
- `IndexedDB['sunoboom-song-media-v1']` — бинарные аудио/медиа.
- `localStorage['sunoboom-ui-settings-v1']` — настройки интерфейса.

Перед изменениями **проверять актуальные ключи и схемы в исходниках**. Не очищать storage; при изменении формата нужна совместимая миграция. Не создавать параллельный Vue store для legacy-данных. JSON-экспорт не следует считать полноценной резервной копией бинарных файлов IndexedDB.

**Обмен песней по ссылке:** `#sb-song=...` содержит данные карточки, **не** локальные MP3/M4A/WAV. Проигрывание аудио по приватной внешней ссылке без реального сервера и хранилища не реализовано. Встроенную обложку можно прочитать из поддерживаемых локальных метаданных, если она присутствует.

## 6. Требования к продукту и UI

- Тёмная адаптивная тема, фиолетово-розовые градиенты, существующий визуальный стиль; поддерживать телефон и десктоп.
- Название пользовательского раздела — **«Мастер»**; технический ID `producer` и старые имена файлов сохранять для совместимости.
- Карточка жанра: **вертикальное меню** («ЖАНР-НАВ»), не возвращать горизонтальную ленту.
- История версий рядом с логотипом: мажорные/минорные, крупные/мелкие/все обновления, поиск по всем категориям; **не показывать список Git-коммитов как вкладку продукта**.
- Лимит Suno Style/prompt — **1000 символов**; показывать предпросмотр, не изменять слова песни без подтверждения.
- Генератор тегов исполнения: режимы smart/rules/manual, дефолты интенсивность 3/5, `balanced`, мелизмы/фальцет/гармонии включены; шёпот и хрипота исключены по умолчанию.
- Не добавлять по умолчанию эффект живой сцены, толпу, шёпот или хриплый вокал в музыкальные промпты.
- В обсуждениях выбран ориентир на Gemini/«Argon» для будущего ИИ; **не выдумывать доступность модели или API ID**. План нагрузки — **100–150 песен в месяц суммарно для всех участников**, стоимость и качество русскоязычных текстов важны. В коде есть условный `SUNOBOOM_GEMINI_ENDPOINT`, но **рабочий backend не подтверждён**.

## 8. Следующие работы (предложения, а не подтверждённая реализация)

Миграция идёт **небольшими изолированными Vue-этапами с fallback**. Остались неперенесённые экраны и блоки: «Мои песни» и управление дублями, артисты/ДНК, плеер/A-B, настройки кабинета, «Мастер», отдельные инструменты карточек. **Следующий конкретный этап выбирается после проверки текущих файлов и тестов**, не повторяя уже перенесённое.

Отдельные **нереализованные либо не подтверждённые** задачи, которые не смешивать с переносом Vue: реальная авторизация по приглашению, защищённое облачное хранение и ссылки с воспроизведением аудио, синхронизация устройств, production Gemini API и контроль расходов.
