## 1. Суть проекта и адреса

SUNOBOOM — музыкальная мастерская / творческая лаборатория для закрытого круга по приглашению. Основная функциональность: Академия жанров, идеи песен, Suno Studio, аранжировщик, музыкальная поэзия, ДНК артистов, паспорта треков, собственные песни и аудиозаписи, музыкальный плеер, «Мастер», личный кабинет и история версий.

- **Единственный основной репозиторий:** [nick-osinskiy/SUNOBOOM](https://github.com/nick-osinskiy/SUNOBOOM).
- **Основная ветка:** `main`.
- **Сайт:** https://nick-osinskiy.github.io/SUNOBOOM/
- **Публикация:** GitHub Pages из `main`, корень `/`. Точка входа — `index.html`.
- **Продуктовое противоречие:** доступ «по приглашениям» — требование, **не существующий технический контроль**. На момент проверки публичны репозиторий и Pages, нет реальной авторизации и серверных учётных записей. Не описывать продукт как технически закрытый, пока не реализовано ограничение доступа.

## 2. Архитектура и технический стек

- Основной действующий сайт: большой `index.html` со старой разметкой, CSS, данными и обработчиками JavaScript; дополнительные JS/CSS-файлы в корне.
- Постепенный перенос интерфейсов на **Vue 3**, сборка **Vite**, подготовлены **Pinia** и **Vue Router**. На 0.107 существующие функции `go()`, `view.nav`, `render()` и старые данные остаются источником истины. Vue Router не должен внезапно подменить навигацию, Pinia — дублировать локальное хранилище.
- `src/vue/entry.js`: единая точка входа Vue, `mountVueFeature()`, `unmountVueFeature()`, запуск feature-bridges.
- `src/vue/bootstrap.js`: загрузчик; в production Vue включается метатегом `<meta name="sunoboom-vue-nav" content="enabled">` в корневом `index.html` (на 0.107 **включён**).
- `src/vue/VueFeatureHost.vue`: монтирование Vue только в выделенный контейнер; сохранять fallback старой HTML-реализации. **Не заменять весь `#app`**; нельзя одновременно отдавать Vue и старому `render()` контроль над одним DOM-узлом.
- `vite.config.js`: сборка `src/vue/entry.js` в `dist/vue/sunoboom-vue.js` и `sunoboom-vue.css`, без замены корневого сайта.
- `.github/workflows/vue-navigation.yml`: workflow сборки и проверок, умеет коммитить проверенные `dist/vue` assets в `main`. Не менять публикацию, секреты, права или Actions без отдельного разрешения.
- `tests/vue-navigation.test.mjs`: тест соответствия навигации; `tests/vue-browser-smoke.mjs`: браузерная проверка Playwright для мобильного и десктопного экранов с production Vue bundle.

Команды:
```bash
npm install
npm run test:vue-nav
npm run build:vue
npm run test:vue-browser
```
Тесты требуют подходящего Node.js (см. `package.json`) и для Playwright — Chromium. Отсутствие подтверждённого успешного запуска не выдавать за «тесты пройдены».

## 6. ИИ и музыкальные правила

- Предпочтительный ориентир для будущей интеграции — семейство Gemini, ранее обсуждавшийся **Argon**, но только если официальный API действительно предоставляет соответствующую модель: никаких вымышленных model ID.
- Расчётная нагрузка: **100–150 песен в месяц суммарно для мастерской**, приоритет — русские песни, музыкальные структуры, вокальные теги, качество и контролируемые затраты.
- В `performance-tags.js` присутствует условная интеграция через `SUNOBOOM_GEMINI_ENDPOINT` / meta endpoint, ручное согласие на отправку и локальный fallback. Наличие кода **не означает** настроенный сервер или секреты.
- Нет подтверждения, что Suno API или реально действующий Gemini backend подключены; любые API интеграции проверять в репозитории и через разрешённые настройки до заявления о готовности.
- Suno Style/prompts: лимит **1000 символов**; беречь исходные тексты, показывать preview и запрашивать ручное подтверждение. Не добавлять сценический/толповый эффект, шёпот и хриплый вокал по умолчанию.
- Режимы performance tags: smart/rules/manual; дефолты 3/5, balanced, melisma/falsetto/harmonies=true, noWhisper/noRasp=true, если пользователь их не изменил.

## 7. Утверждённые дизайн и правила разработки

- Сохранять существующий тёмный адаптивный визуальный язык: фиолетово-розовые градиенты, текущие карточки/кнопки/типографику, отдельные мобильные и десктопные состояния.
- Бренд **SUNOBOOM**; название пункта для пользователей — **«Мастер»**. Не переименовывать без нужды технические `producer`, названия файлов и структуры сохранений.
- Версия рядом с логотипом и доступная по нажатию история версий: мажорная/минорная; крупные/мелкие/все обновления; глобальный поиск; без списка отдельных коммитов внутри интерфейса.
- Работать **только в основном репозитории**; никаких отдельного HTML-прототипа, нового сайта или нового репозитория без указания.
- Сначала проверить относящиеся к задаче файлы, затем внести минимальное изменение, проверить сборку/тесты и записать в GitHub. Не писать «готово», пока коммит не подтверждён.
- При отказе Vue сохранять старые работающие элементы. Не менять маршрутизацию/схемы данных/доступы/настройки развёртывания без необходимости и разрешения.
- После существенного изменения по согласованию обновлять этот документ, записывать новые точки входа, зависимости и фактические ограничения.

## 10. Этап v0.109 — библиотека на Vue 3

- Экран «Личный кабинет → Избранное / Моя библиотека» переносится в `src/vue/account/LibraryCollection.vue`, bridge — `src/vue/account/legacyLibraryBridge.js`.
- `library-vue-bridge.js` оборачивает исходный `saved()` в отдельный контейнер, не заменяя старую разметку при выключенном Vue. Snapshot использует исходные `data.favorites`, `data.savedIdeas`, `data.manualIdeas`, `data.savedGeneratedIdeas`, `data.savedPrompts` без новых ключей хранения.
- Vue отвечает за пять коллекций и карточки, исходные делегированные `data-action` отвечают за открытие жанров, переход в Studio, копирование, сохранение/удаление идей и промптов и открытие редактора.
- Список обновляется после прежнего `render()`, при недоступности Vue остаётся исходная библиотека. Выполнение тестов и публикацию сверять по Actions, не выводить из самого наличия исходников.

## 13. Этап v0.112 — подробная карточка «Мои песни» на Vue 3

- `src/vue/account/SongDetail.vue` + `legacySongDetailBridge.js` заменяют только HTML-подробности выбранной песни после монтирования Vue.
- Источник истины — `my-songs.js`: `SUNOBOOM_LEGACY_SONG_DETAIL.snapshot()` сообщает поля карточки и HTML оригинального `versionManager(song)`. Хранилище `sunoboom-my-songs-v1` и файлы `sunoboom-song-media-v1` не преобразуются.
