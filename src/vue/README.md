# SUNOBOOM — постепенный переход на Vue 3

Этот каталог — **часть существующего SUNOBOOM**, а не новый сайт или отдельный HTML-прототип.

## Этапы 1–2 (подготовка и исходный код Vue-навигации)

- Добавлены Vue 3, Pinia, Vue Router и Vite в `package.json`.
- `src/vue/entry.js` экспортирует `mountVueFeature(target, component, props)` и `unmountVueFeature(target)`.
- `VueFeatureHost.vue` позволяет подключать новые Vue-компоненты **только к заранее выделенным контейнерам**.
- `vite.config.js` компилирует лишь Vue-слой в локальный `dist/vue/`. Сборка **не публикуется** и не заменяет корневой сайт.
- `index.html`, текущие CSS/JS-модули, история версий и настройки GitHub Pages остаются без изменений.

## Команды для разработки

```bash
npm install
npm run dev
npm run build:vue
```

`npm run dev` обслуживает существующий `index.html`; пока Vue-компоненты к нему намеренно не подключены.
`npm run build:vue` собирает **только подключаемый Vue-модуль**, а не весь сайт.

## Неприкосновенные данные и правила следующего этапа

- Сохранить `localStorage['sunoboom-v1']`, `localStorage['sunoboom-my-songs-v1']`, `localStorage['sunoboom-ui-settings-v1']` и IndexedDB `sunoboom-song-media-v1`.
- Не заменять глобальный `#app` целиком: переносить конкретный раздел за раз.
- Не допускать одновременного управления одним DOM-контейнером Vue и существующим `render()`; вызывать функцию размонтирования до перерисовки legacy-приложения.
- Перед изменением механизма публикации провести полноценную сборку и тестирование страниц, мобильной навигации и сохранённых данных.
- Vue Router пока **не подключён к действующей навигации**; сначала понадобится спроектировать совместимость с `go()` и `view.nav`.
- Отсутствие мигрированной функции не должно приводить к появлению заглушек вместо уже существующей функции.

## Этап 2 — перенос боковой и мобильной навигации

- `navigation/NavigationMenu.vue` отображает существующий `navs` без жёстко прошитого списка.
- `navigation/nav-model.js` рассчитывает активные пункты, включая `detail` → Академия и страницы кабинета.
- `navigation/legacyBridge.js` наблюдает только за заменой корня `#app` и монтирует Vue в два специальных контейнера.
- В `index.html` добавлен read-only snapshot/переход через текущую функцию `go()`; исходные кнопки сохраняются как fallback.
- В локальном Vite dev-сервере навигация подключается автоматически. На **опубликованном GitHub Pages Vue-навигация ещё НЕ включена**, пока не собран и проверен `dist/vue/sunoboom-vue.js`.
- Чтобы включить проверенную production-сборку позже, добавить `<meta name="sunoboom-vue-nav" content="enabled">` и опубликовать собранный модуль **в том же коммите**. До этого сохранён старый интерфейс без сетевых зависимостей от CDN.
- `node --test tests/vue-navigation.test.mjs` проверяет маршруты и динамический пункт «Мастер», без npm-пакетов.

`Vue Router` и `Pinia` пока не перехватывают существующие данные или маршруты, они подготовлены для будущих этапов.

## Этап 3 — проверяемая production-сборка

- `npm run build:vue` создаёт `dist/vue/sunoboom-vue.js` и `dist/vue/sunoboom-vue.css`.
- `npm run test:vue-nav` проверяет соответствие существующим маршрутам.
- `npm run test:vue-browser` использует Playwright/Chromium, проверяя обе навигации и переходы через действующие страницы с готовой production-сборкой.
- Workflow `.github/workflows/vue-navigation.yml` запускает сборку и браузерные тесты в GitHub Actions. **Только если все проверки прошли**, он сохраняет собранные assets в `dist/vue/` внутри того же репозитория.
- Никаких настроек GitHub Pages workflow не меняет; Vue-меню сайта будет включено отдельным коммитом **только после подтверждённого успешного результата**.
- Загрузчик сначала проверяет признак production-режима, что позволяет тестировать production-бандл и по локальному адресу.

## Этап 4 — карточки жанров Академии на Vue 3

- `academy/GenreCards.vue` рендерит карточки жанров из основной `GENRES` базы, без копирования энциклопедии.
- `academy/legacyAcademyBridge.js` подключает Vue только к сеткам внутри `#catalog-cards`, в том числе во вложенных разделах религиозной музыки.
- Родительские `<details>`, иерархия религий, поиск с приоритетом названий, подписи и счётчики остаются в действующем HTML/JS.
- Поиск пересоздаёт карточки по существующим правилам; мост повторно монтирует Vue после обновления списка.
- Клик по карточке продолжает идти через существующий `data-action="genre"`, включая сохранение истории просмотров.
- Если Vue не загрузится или не получит полную модель, исходные карточки остаются доступными.
- Нет изменений пользовательских ключей `localStorage` и хранилища IndexedDB.

Расширение на поисковую строку, группы и страницу жанра выполняется отдельно после проверки этого этапа.

## Этап 5 — реактивный каталог Академии

- `academy/AcademyCatalog.vue` рендерит поиск, число результатов, музыкальные семейства и вложенные религиозные разделы.
- Ключевые правила поиска (включая «ска», исполнителей и приоритет названий) **не дублируются**: Vue вызывает уже существующий `sbAcademySearchSelection()` через защищённый read-only мост.
- Модель для Vue создаётся на лету из `GENRES`, `familyOrder`, `CATALOG_GROUP_META` и `SACRED_HIERARCHY`; копий каталога и миграции данных нет.
- Поиск, раскрытие групп и счётчики становятся реактивными. Состояния раскрытия возвращаются в прежние `view.catalogExpanded`, `view.sacredReligionsExpanded` и `view.sacredBranchesExpanded`.
- Начальный HTML по-прежнему создаётся старым `newCatalog()` и используется в случае недоступности Vue.
- `filterCatalog()` не вмешивается во Vue-узлы во время активного Vue-рендера, но продолжает работать в fallback-режиме.
- Тесты в Chromium проверяют обе ширины, раскрытие религиозной иерархии, поиск «ска» и открытие карточки.

## Этап 6 — страница жанра на Vue 3

- `academy/GenreDetail.vue` управляет шапкой жанра, характеристиками и вертикальной навигацией `ЖАНР-НАВ` на всех экранах.
- Вкладки «Обзор», «Идеи песен», «Промпты Suno» и «Исполнители» переключаются реактивно, без полного перерендера страницы.
- `window.SUNOBOOM_LEGACY_GENRE` возвращает сведения о выбранном жанре и HTML уже существующих генераторов вкладок, включая все расширения исполнителей и заготовки Suno. Сами генераторы пока остаются на JS для совместимости.
- Все вложенные кнопки вкладок используют прежний делегированный `data-action` — добавление в избранное, создание в Suno и переход назад остаются на существующих функциях.
- `brightDetail()` продолжает создавать исходную HTML-разметку внутри `#sb-vue-genre-detail`, которая работает без Vue и используется как fallback.
- Не изменены жанры, тексты, подсказки, артистические базы, `localStorage` или IndexedDB.
- Браузерные тесты проверяют переключение всех четырёх вкладок, избранное и возврат в каталог с прежним поиском на компьютере и телефоне.

Следующая задача: перенос отдельных сложных содержательных блоков на Vue-компоненты без дублирования жанровых справочников.

## Этап 7 — Vue 3: обзор жанра и расширенные исполнители

- `GenreOverview.vue` полностью рендерит «Характер и звучание», инструменты, стиль, темы, первые три идеи, паспорт жанра, подборку исполнителей и переходы в идеи/Suno Studio.
- `GenreArtists.vue` использует **уже расширенные** `ARTIST_PAGES` и `RU_ARTISTS` через функцию `window.SUNOBOOM_ARTIST_CATALOG` внутри `artists-expanded.js`. Каталоги и классификация исполнителей не дублируются.
- Сцены «Мировая» и «Русскоязычные», поиск по артистам/произведениям и фильтры «Все / По жанру / Смежные» работают реактивно.
- Полные профили исполнителей и избранное предоставляет действующий `artist-profiles.js`: его обработчики и сохранённые данные остаются без изменений, а новые Vue-карточки получают уже существующие кнопки.
- «Идеи песен» и «Промпты Suno» пока оставлены на проверенных генераторах HTML без потери пользовательских действий.
- Сохранены резервные версии содержимого через `brightOverview()` и `artistView()`, не затронуты localStorage/IndexedDB.
- Дополнены браузерные тесты: сцены, поиск, фильтры, полный профиль, реактивная навигация и сохранение прежних действий.

## Этап 8 — Vue 3: идеи песен и промпты Suno

- `GenreIdeas.vue` отображает все идеи текущего жанра из существующего `GENRES` с сохранёнными названиями, настроениями, описаниями и индексами.
- Кнопки «Сохранить / Сохранено» сохраняют исходные обработчики `idea-save`, исходный ключ `savedIdeas` и пользовательскую библиотеку; сохранение остаётся доступным после повторного открытия карточки.
- «В студию» продолжает использовать `idea-use`, перенося название и сюжет идеи, темп и настроение в существующий конструктор.
- `GenrePrompts.vue` отображает неизменённые шаблоны «Оригинальное звучание» и «Мягкая атмосфера» и использует `use-genre` и `use-soft`, не заменяя алгоритм построения промпта.
- Вкладки «Обзор», «Идеи песен», «Промпты Suno», «Исполнители» теперь представлены отдельными Vue-компонентами.
- Обновлены тесты Chromium для проверки сохранения идей, возврата в каталог, обеих версий промптов и передачи настроек в Suno Studio. База и хранилища без миграций.

## Этап 9 — Suno Studio: Vue 3 конструктор промптов

- `studio/StudioBuilder.vue` управляет основными параметрами: жанр, настроение, вокал, язык, энергия, BPM, тема, дополнительные инструкции, ограничения звучания.
- Реактивный вывод промпта и счётчик символов по-прежнему получают текст из **действующей `promptValue()`**; её модификации жанровым миксером и лимит 1000 символов сохранены.
- Копирование и сохранение промпта выполняют прежние `data-action="copy-prompt"` и `data-action="save-prompt"`, без нового хранилища.
- `window.SUNOBOOM_LEGACY_STUDIO` использует существующие `builder`, `GENRES` и `updateBuilder()`. Уведомление `sunoboom:studio-updated` синхронизирует Vue с изменениями, сделанными аранжировщиком или другими модулями.
- Vue монтируется **внутрь** неизменённого `.studio-grid`; обёртки студии, жанровый миксер, конструктор аранжировок и аудитор промптов не удаляются.
- При недоступности JS-сборки работает исходная HTML-форма Suno Studio.
- Браузерный тест проверяет форму, выходной промпт, лимит 1000 символов, запись в библиотеку, внешнюю синхронизацию, смену жанра и присутствие встроенных инструментов.

## Этап 10 — Vue 3: отдельный жанровый миксер

- `studio/GenreMixer.vue` использует существующие CSS-классы и разметку жанрового миксера.
- `window.SUNOBOOM_LEGACY_MIXER.snapshot()` предоставляет текущее состояние `GENRES`, `data.mixerDraft` и `data.savedMixes`, не создавая второго хранилища.
- Алгоритмы пропорций, сборки Style-промпта, сохранения и передачи в Suno Studio остаются в `genre-mixer.js`.
- Событие `sunoboom:mixer-updated` синхронизирует Vue при изменении ползунков и настроек. Полный legacy `page()` остаётся fallback.
- Playwright проверяет ввод, баланс, сохранение и передачу в Suno Studio на компьютере и телефоне.

## Этап 11 — Vue 3: интеллектуальный аудитор промптов

- Компонент `studio/PromptAuditor.vue` отображает оценку, замечания, ручной ввод и редактируемый предпросмотр, используя существующие `sbpa-*` классы CSS.
- `window.SUNOBOOM_LEGACY_AUDITOR.snapshot()` поставляет структурированный результат *того же* `inspect()` и `propose()`, что используют прежние HTML-генераторы; дублирования алгоритмов нет.
- `sunoboom:auditor-updated` переключает обновления результатов на Vue без изменения DOM внутри смонтированного компонента. При недоступном Vue сохраняется старый `resultMarkup()`.
- Режимы Studio/свой текст, переход из «Мои промпты», жанровый поиск, подтверждение копирования и неизменность исходника продолжают работать через прежние `data-sbpa-action`.
- Браузерный тест проверяет обе ширины, реакцию на обновления Studio, конфликтующие BPM, повторы, ручной предпросмотр и импорт текущего промпта в ручной режим.

## Этап 12 — Vue 3: визуальный аранжировщик

- `studio/ArrangementPanel.vue` в четырёх режимах отображает карточки блоков, drag-and-drop-змейку, панель музыкальных переходов и энергетический график.
- `studio/legacyArrangerBridge.js` встраивает компоненты только в исходные контейнеры `#sba-cards`, `#sba-snake-track`, `#sba-transition-hub-list`, `#sba-energy-chart`. При отсутствии сборки работает прежний HTML-рендеринг.
- `SUNOBOOM_LEGACY_ARRANGER.snapshot()` предоставляет состояние существующих структур, не создавая параллельное хранилище и не копируя музыкальную логику.
- Оригинальные подсказки и меню инструментов Академии, редакторы переходов, пресеты, Lyrics/Style, проверка 1000 символов и подтверждение импорта в Studio продолжают работать через исходные обработчики.
- `sunoboom:arranger-updated` синхронизирует Vue; legacy-код не заменяет разметку в смонтированных контейнерах.
- Playwright на компьютерной и мобильной ширине проверяет редактирование, перестановку, жанровые рекомендации, переходы и данные черновика.

## Этап 13 — Vue 3: меню шаблонов, библиотека инструментов, Lyrics/Style

- `studio/ArrangementPicker.vue` управляет меню шаблонов, его фильтрами и поиском по полной Академии. Источник информации — `genreChoices()`, `PRESETS` и `familyOrder` в исходном `arrangement-builder.js`.
- В `studio/ArrangementPanel.vue` вместо строки HTML подключён нативный интерфейс библиотеки инструментов и приёмов: поиск, смена жанра и добавление звука; данные приходят из прежнего `soundSuggestions()`.
- `studio/ArrangementResult.vue` отображает Lyrics, Style, сообщение и подтверждение переноса в Studio. Подготовка, лимит 1000 символов и применение по-прежнему выполняются исходными функциями.
- Vue-компоненты подключаются в существующие `.sba-preset-picker`, `.sba-result` и `#sba-cards`, без изменения дизайна и хранилища.
- Обновления legacy DOM не перезаписывают Vue-разметку; прежние HTML-генераторы остаются резервным вариантом при недоступности Vue.
- Playwright проверяет две ширины, поиск Академии, сохранность ручных инструментов, вкладки, отмену и подтверждение изменения Style, сохранение выбранного пресета.

- `src/vue/navigation/legacy-router-mirror.js` создаёт реальный **Vue Router 4 с `createMemoryHistory()`**, но **не перехватывает** `go()`, `openGenre()`, `view.nav`, `window.history` и URL. Задача этого этапа — ввести совместимое представление маршрута, не меняя работу сайта.
- `syncLegacyRoute()` обновляет общий реактивный маршрут v0.130 немедленно и независимо синхронизирует Vue Router в памяти. Промисы переходов упорядочены, чтобы быстрые переключения не оставляли зеркало на старом экране; сбой зеркала логируется и не блокирует старые переходы.
- Базовые страницы зеркалируются как `/studio`, `/producer`, `/catalog`; вложенная карточка жанра — `/catalog/detail`, разделы кабинета — `/account/tracks`, `/account/myideas` и т. п. Эти пути — **внутренние**, не настоящие адреса GitHub Pages. Vue Router пока не установлен в корень страниц и не рисует их.
- Диагностический read-only метод `window.SUNOBOOM_VUE_ROUTE.routerSnapshot()` показывает текущее положение зеркала. Исходные меню, действия, данные, офлайн-поведение и fallback без Vue остаются прежними.
- Unit tests проверяют пути и быструю смену экранов; Playwright для desktop/mobile — память роутера, отсутствие изменения URL, жанровую карточку, «Мастер», паспорт трека и работающий fallback.
